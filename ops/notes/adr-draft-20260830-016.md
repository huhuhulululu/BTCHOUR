## 背景

- **真单事实**（LEARN 014/388 已对 sqlite）：373–388 是弱跌噪声家族。382–388 七张真挂挂时动量 −15 到 −0.2，无一张同向 |impulse| ≥ $100；「成交 ⇔ 方向失败」12 次实证；14 张成交净 +0.0677 全靠人工救回的 378（+0.2325）撑着，剔除后 −0.1648。388：挂时 −0.175（家族史上最弱）、成交落在 77.7s journal 盲区正中、t_scratch −0.0708（出场滑 6 tick = 本金 24%）。
- **引擎事实一（A 的题）**：live_one 由交易所成交直接 promote，005「成交仍要同向 $100」只对纸盘 rest 生效——**真单反而没有成交门**。
- **引擎事实二（B 的题 = 015）**：rest 0.25 要求市场先给 8¢ 逆向折扣，构造上「只成输单、排除赢单」；AUG2520 人手是砸盘启动时买在**市场正在交易的价**。386 真 dump 峰时 ask ≤ 0.25，构造性不可挂。这是错位，不是阈值松紧。

## 选项

**A — 只修 live 成交门**：真单成交也要同向 |impulse| ≥ $100 才 promote，否则按无效成交处理（细则 ENG 定，013 对账不变）。修的正是 014 背景点名的引擎漏洞。单独上的缺陷：live 已停，A 独走等于修一扇关着的门；不碰构造错位，重开后 rest 0.25 仍只成输单；journal 盲区内此门形同虚设。

**B — 只做 015 rest 语义**：砸盘确认（同向 ≥ $100、32–42¢ 带内看见）时挂在**砸盘正在交易的价**，仍 post-only、不吃 taker，不再强制 8¢ 逆向折扣。对准 AUG2520 的人手构造。单独上的缺陷：挂在交易价 = 成交显著变快，若无 A 的成交门兜底，弱跌噪声会**更快更多**地成交——B 独走比现状更危险。

**C — A+B 捆绑（推荐）**：挂门（同向 ≥ $100 且带内看见，即 014 停机门延续）+ 挂价（正在交易的价，post-only）+ 成交门（真单同向 ≥ $100 才 promote）三件一致。先只在**纸盘**生效攒证据，014 停机不动、真钱零暴露。前置：ENG journal 断档修复；进 decisions 定稿前须 ADV 对开（并入 384/386/387/388 既有题）。重开 live 仍按 014 三条件**另行请示**，不在本条内。

**D — 维持 014 停机、不加改动**，等纸盘在现行门下自然出金带：最安全，但 LEARN 已判现行门唯一可挂形态「ask 下行穿带 × 动量未衰」全史样本仅 1（AUG2608），纸盘静默大概率是门在执行而不是在变好；对「如何优化」的回答等于「不优化」。

## 推荐

**C（待用户）**，分两步：
1. 纸盘立即按 C 语义攒证据；live_one 保持 014 停机，无任何真钱暴露。
2. ENG 修断档 + ADV 对开通过 + 纸盘打出 AUG2608 型之后，按 014 三条件**单独请示**是否重开 live_one。

理由：A、B 各只修半个构造——A 管「让谁成交」不管「挂在哪」，B 管「挂在哪」不管「让谁成交」；连续割肉是两者叠加的产物（弱跌也能挂 → 挂在只成输单的价 → 真单无成交门直接落账）。只有捆绑才同时回答「挂给谁、挂在哪、让谁成交」，且与金带子构造逐条对齐。
